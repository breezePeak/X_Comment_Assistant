# X 评论助手 v1.1.0

无需构建的 Chrome Manifest V3 扩展：在侧边栏开启助手后，点击 X 帖子的回复按钮，读取该帖并调用你选择的 AI 厂家和模型，生成一条简短回复并自动复制到剪切板，由你粘贴、检查并手动发布。

## 功能

| 功能 | 说明 |
| --- | --- |
| 手动开启与关闭 | 默认关闭；点击侧边栏「开启助手」后才读帖和生成，关闭时取消等待中的生成。 |
| 点击回复即读帖 | 从 X 网页 DOM 读取正文、作者、链接和引用内容，也支持补读已打开的回复弹窗。 |
| 单条回复并复制 | 点回复后生成一条简短候选并自动复制到剪切板；可在侧栏编辑后手动复制，不会自动发送。 |
| 主帖与评论上下文 | 回复评论时结合已加载的主帖背景，区分主帖作者与当前评论者。 |
| 外语中文参考 | 外语候选附完整中文译文，复制时只复制评论原文。 |
| 多厂家、多模型 | 每家使用独立地址与 Key，通过按钮逐个添加模型，统一在设置页切换。 |
| API 连通测试 | 向选定模型发送 `1+1=？`，显示实际回答和耗时。 |
| 紧凑侧边栏 | 帖子默认两行预览，评论框自动增高，支持展开全文和手动重新读取。 |
| 热点图文池 | GPT bot 通过带 Token 的 POST 接口入库，插件展示正文、配图和来源，由你选择发布。 |
| 消费状态 | 发布成功后点击“我已发布”，默认隐藏；可查看已消费帖子并恢复。 |
| 未回关查看 | 读取自己关注列表中当前已加载的账号，列出未显示回关标记的账号，并逐个打开 X 原生取消关注确认框。 |
| 我的帖子数据 | 浏览自己主页时连续采集（含本人引用帖），互动变化才更新，自动上传服务端 SQLite，支持排序、时段汇总与导出。 |

## 采集自己的帖子与互动数据

双击 **[server/启动本地服务.cmd](server/启动本地服务.cmd)**（需 Node.js 24+），本机服务后台启动，**无需 Docker 或 Token**。重新加载扩展并刷新 X，插件默认连接 `http://127.0.0.1:12345`。之前填过远程地址时，在设置中点击「使用本地默认」。进入自己的主页后自动开始采集，滚动加载的新帖子会持续累计，无需点击采集按钮，也无需打开侧栏或开启评论助手。侧栏「我的数据」默认监听 `https://x.com/1nhkjltx`，可在右上角设置页的「我的数据」中填写并保存其他个人主页地址。切换到数据时立即检查页面，返回配置主页或滚动时自动采集。「帖子数据」查看和导出帖子，「数据分析」展示各项指标总量、篇均、有效样本数和发帖时段的平均浏览图表，随采集更新。只展示本机采集缓存，不读取服务端历史记录；无需启动服务也可采集和导出，启动服务后继续自动上传。

采集到的帖子先按 ID 对比本机数据：互动数、正文等均相同则不重复保存或上传，滚动时发现互动发生变化或长文已展开后更新原记录。服务端按「账号 + 帖子 ID」去重，较旧快照不能覆盖较新快照。返回配置主页或在主页滚动（滚轮、触控板等）时读取页面，缓存在内存，约 400ms 合并写入本机待上传队列，再自动分批发送；不替你滚动页面，不调用 X 私有接口。不监听整页 DOM 变化；导航或滚动后约 800ms 补读一次，收录异步渲染的帖子。

只收录配置主页账号发布的帖子，**包括本人发出的引用帖**。本人主页里转发的他人原帖、推荐的他人帖子不会入库；引用内容单独保存，指标只读取本人这条引用帖，引用原帖的互动与媒体不计入本人指标。也可在自己的「回复」页采集本人回复，时段汇总会一并统计这些记录。

保存字段：帖子 ID、链接、本人正文、引用文字、发布时间、采集时间、引用帖与本人图片/视频标记、正文是否可能截断，以及浏览、赞、回复、转帖、收藏的页面可见数量及原始显示文字。缺失指标为 `null`，CSV 中为空；K / M / 万等页面缩写换算后可能为近似值。长文请先在 X 展开再采集；不会自动补取未加载的帖子、图片原文件、点击率、关注转化或 X 官方完整分析数据。

界面提供浏览量、互动比、发布时间排序，以及本地时区的发帖小时平均浏览与样本数。互动比为 **（赞 + 回复 + 转帖）/ 浏览**，缺少任一必要指标或浏览为 0 时不计算，不等同于 X 官方互动率。每条数据来自各自最近一次采集，帖子存续时间、内容和样本量都会影响比较，不能仅凭时段平均值推断最佳发帖时间。

采集数据先保存在本机 `chrome.storage.local`，随后自动存入 `server/data/posts.sqlite` 的 `own_posts` 表，不发送给 AI。本地服务无需 Token；服务未启动时保留待保存队列，后台每分钟重试，重启浏览器后仍可继续。仍兼容自定义远程服务与 Token；服务地址改变时会把本机记录重新排队发送到新地址。

**成功入库的记录不受插件卸载或重装影响。** 服务端记录保存在 `server/data` 文件夹中；侧栏只读取本机采集缓存，不从服务端恢复。卸载或清除扩展存储后，需重新浏览配置主页采集。

CSV 可用表格软件分析，JSON 保留完整字段与原始帖子 ID（表格软件可能把长数字 ID 转为科学计数法）。「清除本机缓存」需确认，会删除当前账号本机记录及待上传项，服务端已上传记录保留，本机需重新浏览主页采集；不提供删除服务端历史的入口。存储空间不足会提示并保留原有数据。

## 查看未回关与取消关注

更新扩展后刷新 X，打开侧边栏的「未回关」→「打开我的关注」，自己的「正在关注」列表加载后自动识别，滚动时自动更新，无需手动读取。列表显示账号主页链接和「取消关注」按钮；点击后在 X 原生弹窗核对并确认，网页列表变化后侧边栏自动刷新。持续监听滚轮、滚动及列表变化，切换账号或标签页时重新识别。此功能无需开启评论助手或配置 API。

仅检查 X 网页当前加载在 DOM 中的账号，滚动时自动更新；每次识别替换当前结果，不累计，也不表示已经检查全部关注。依据 X 的「关注了你」标记筛选，标记未加载或 X 改版可能影响判断，请核对账号关系后操作。不会批量取消关注，不读取 Cookie 或调用 X 私有接口。

运行 `node --test tests/following.test.mjs` 验证自动识别与取消前校验；配置好 Playwright 与 Chrome 后，运行 `node tests/following-browser.cjs` 验证进入视图自动读取、滚动识别、异步回关标记、页面隔离与确认后刷新。

## 热点帖子服务（v1.1.0）

新增独立的 Node.js 24 + SQLite 服务，本机一键启动免 Token，远程部署保留 Bearer Token；支持重复入库去重、图片持久保存、分页、消费和恢复。现有 GPT bot 继续负责定时生成，服务端不额外调用模型。

部署文件、接口示例及 bot 对接说明见 **[server/README.md](server/README.md)**。插件设置页增加“热点帖子服务”，独立保存服务地址和 Token；侧边栏切换“热点帖子”即可使用，无需开启评论助手或填写评论 AI Key。发布后需要你手动点击“我已发布”，复制与下载不会自动消费。

## 安装与更新

安装无需 Node.js、npm 或打包工具。先克隆本仓库，或从 GitHub 的 **Code → Download ZIP** 下载并解压：

```sh
git clone https://github.com/breezePeak/X_Comment_Assistant.git
```

1. 使用 Chrome 116 或更新版本，打开 `chrome://extensions` 并开启「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本项目的 **extension 文件夹**，不要选择项目根目录。
3. 如果使用 ZIP 安装包，先解压，再加载包含 `manifest.json` 的文件夹。
4. 固定插件图标，刷新已经打开的 X 页面，打开侧边栏，点击齿轮进入 API 配置。

更新时用新版文件覆盖**原来的插件目录，保持路径不变**，点击扩展的「重新加载」，刷新 X 并重新打开侧边栏与设置页。v1.1.0 会保留旧版的厂家、地址、Key、模型列表、语言和写作偏好；侧边栏底部显示版本号。评论功能更新后需要先开启助手，热点帖子独立可用。

**日常使用：**打开 X → 点击插件图标打开侧边栏 → 点击「开启助手」→ 点击目标帖子的回复按钮 → 检查回复对象和生成的回复 → 从剪切板粘贴到 X，检查后手动发布；需要新回复时点「重新生成并复制」。

## 开启与关闭

- 评论助手初始为关闭状态。关闭时评论模块不监听 X 的回复点击、不观察帖子 DOM 变化，重读与评论生成入口不可用；后台收到迟到的选帖消息也会忽略。本人主页自动采集独立运行，不受评论开关影响。
- 点击侧边栏顶部「开启助手」后，等待你点击 X 的回复按钮或手动点击「重读帖子」，开启动作本身不会立即读取旧帖子或调用 AI。
- 点击「关闭助手」会撤掉页面中的点击、焦点监听与 DOM 观察，取消当前生成并隐藏当前结果。已经到达服务商的请求仍可能计费。
- 开关对当前浏览器会话的所有 X / Twitter 标签页生效；切换标签页和重新打开侧边栏会保留开关状态，重启浏览器或重新加载扩展后默认关闭。API 配置独立保留。
- 重新开启后仍能选择同一帖子，匹配的会话候选缓存可以继续复用。设置页中主动点击「测试当前模型」仍可测试接口。

## 多厂家、多模型配置

1. 编辑默认厂家，或点击「新增厂家」。每家填写独立名称、API 地址、Key 和模型列表。
2. 在「该厂家的模型」点击「＋ 添加模型」，逐个填写实际模型 ID，每个独立输入框可编辑或删除；再从「当前模型」选择用于测试和生成的模型。旧版文本域中的模型会自动显示为独立行。
3. 点击「保存全部配置并授权」，允许这些 API 域名。每家的 Key 独立保存，新增或删除厂家需要保存后生效。
4. 厂家与模型统一在设置页切换，保存后回到侧边栏点击「重新生成」。主页面不显示厂家或模型信息，不会自动换厂家或重试。

| 配置 | 说明 |
| --- | --- |
| 厂家名称 | 方便自己区分，例如商汤日日新、DeepSeek、自建网关。 |
| API 地址 | 服务商的 Base URL，自动拼接 `/chat/completions`；也接受完整接口地址。 |
| 该厂家的模型 | 用「添加模型」逐个新增实际模型 ID，例如 `sensenova-6.8-flash-lite`；共用所属厂家的地址和 Key。 |
| API Key | 在对应服务商后台申请；每家独立配置。 |

SenseNova 示例：Base URL 为 `https://token.sensenova.cn/v1`，模型 ID 为 `sensenova-6.8-flash-lite`。初始 DeepSeek 地址和模型是示例，可按需替换。

支持标准的 Chat Completions 请求和 `choices[0].message.content` 响应。仅网页聊天登录、Responses 或 Messages 专有接口不能直接使用；HTTP 仅允许本机 `localhost` 与 `127.0.0.1`。

切换编辑的厂家时，未保存的编辑保留在当前配置页；关闭页面会放弃这些未保存编辑。「清除当前 Key」会立即清除当前厂家的已保存 Key，其他厂家不受影响。新增或删除模型保存后生效；删除当前模型会选中该厂家剩余的第一个模型。每家至少保留一个有效模型才能保存。保存配置页会应用页面上选中的厂家与模型。

## 测试接口

选择厂家与模型，点击「测试当前模型：1+1=？」；可以测试未保存的配置，结果显示实际回答与耗时。测试不会自动保存配置，可能消耗少量 API 额度；测试成功后仍需保存才能用于评论生成。

测试只验证接口能返回文本，不保证模型能正确计算或生成合格的三条评论。未授权、鉴权失败、网络异常和空回答会明确提示，60 秒无响应会终止。修改配置或切换厂家会取消旧测试。

## 生成评论

先在侧边栏开启助手，再在 `x.com` 或 `twitter.com` 点击帖子的回复按钮，插件读取网页 DOM 中的原帖正文、作者及引用内容，生成一条简短回复并自动复制到剪切板。回复显示后可在侧栏编辑；编辑后的内容可点击「复制评论」。然后回到 X 粘贴、检查并手动发送。

默认回复更充实、有层次：内容充分时，中文主帖回复约 80—140 字，评论回复约 50—100 字，外语约 30—45 词；每条原文最多 280 个 Unicode 字符。允许自然使用贴合语境的诗词、典故和比喻，同时要求不编造出处、不堆砌辞藻，不为凑长度捏造内容。实际长度与写作质量仍由模型决定。

非中文候选在原文下方显示「中文参考」，同一次生成同时返回原文与完整译文，不额外发起翻译请求。「复制评论」仅复制原文；中文译文不计入原文字符数。编辑原文后会提示译文对应编辑前内容。模型漏掉外语候选的中文译文时会明确报错，可以展开原始回答检查并重新生成。

回复帖子下面的评论时，同时读取详情页中已加载的主帖，或回复弹窗中显示的上文，分别发送主帖背景和直接回复的评论，生成「自然回应」「轻松互动」「友好延伸」三条候选。主帖滚出页面 DOM 后，在同一详情页内保留已读背景；切换详情页后清除。无法读到主帖时侧边栏会提示，模型只根据当前评论作答，不猜测背景。推荐区帖子不附带当前主帖。

侧边栏默认将主帖和回复对象各压缩为两行预览，点击「展开全文」可查看完整的已读取文字；预览折叠不会截断发送给 AI 的正文。「语言与回复要求」默认折叠，评论框随文字和窗口宽度自动增高，避免框内滚动。窗口较矮或评论较长时，整个侧边栏仍可能需要滚动。

回复弹窗已打开时，打开侧边栏会补读，也可点击「重读帖子」。原帖没有链接时仍能读取文字；可明确匹配同作者和正文的时间线帖子时恢复真实链接，不会猜测 URL。未连接页面时会提示刷新 X。

语言与偏好可在配置页设置，侧边栏支持本次语言和补充要求。切换帖子、厂家或模型会取消旧请求，避免串帖或串模型。候选按标签页暂存于当前浏览器会话，仅复用匹配帖子、厂家、模型和默认写作配置的当前缓存。刷新或关闭标签页会清除对应缓存；直接编辑候选框的文字不会写入缓存，切换前请先复制。

## 模型回答格式

兼容规范 JSON、说明或代码块包裹的 JSON、评论数组、字符串数组以及三条按 `1.`、`2.`、`3.` 编号的评论。双语 JSON 使用 `text` 和 `translation` 分别存放原文与中文译文；编号文本可用单独一行 `中文译文：…`。仍检查三条、非空、不重复、原文和译文长度，不会把任意一段文字硬拆成三条。根据文字脚本识别主要语言，极短混合语句仍需人工核对。

无法识别时可展开「查看模型原始回答」检查最终回答，最多显示前 10000 个字符；服务商标记截断时会明确提示。只读取 `content`，不把 SenseNova 的 `reasoning` 字段当作评论。不自动发起额外付费修复请求。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 点击回复后仍显示等待选择帖子 | 先在侧边栏点击「开启助手」；更新扩展后刷新 X，打开回复框，再点击「重读帖子」。 |
| 提示没有主帖背景 | 回到主帖详情页并等待正文加载，再选择要回复的评论；插件不会通过 X 接口补取未加载的内容。 |
| 1+1 测试正常，但生成失败 | 连通成功只表示接口能返回文本。展开模型原始回答，检查是否有三条候选、外语候选是否附中文译文，以及是否被服务商截断；必要时更换模型。 |
| API Key 无效、余额不足或请求受限 | 在服务商后台检查 Key、权限、余额和额度；确认模型 ID 属于当前厂家。 |
| 修改厂家或模型后没有应用 | 在设置页保存全部配置，回到侧边栏点击「重新生成」。只测试接口不会保存配置。 |
| 外语原文编辑后中文没有变化 | 中文参考对应生成时的原文，不会在每次编辑时调用接口；可重新生成，或人工核对修改后的表达。 |
| 无法复制 | 选中候选原文后按 `Ctrl+C`；插件不会替你填入 X 回复框。 |

## 隐私与限制

- 读取网页 DOM，插件不调用 X 的帖子数据接口，不自动遍历时间线，不读取登录 Cookie 或私信。进入自己的主页或回复页时，会自动累计已加载的本人帖子与可见互动数，并发送到配置的帖子服务入库；引用内容也会随本人引用帖上传。
- 助手开启期间，点击回复或手动重读后，将当前回复对象及已读取的主帖背景（文字、作者、链接、引用内容和媒体标记）直接发送至你选择的厂家；API 服务商的处理政策以该服务商为准。
- 所有厂家 Key 只保存于本机 `chrome.storage.local`，仅供扩展自身页面访问，不云同步，不经过本项目服务器。存储不是加密保险箱，请使用可信设备。
- 安装时申请 X / Twitter 网站访问、侧边栏、存储、写剪贴板及后台定时重试；保存时按填写的厂家或帖子服务申请域名访问，模型测试仅申请当前厂家域名。移除配置不会撤销旧域名授权，可在 Chrome 扩展权限设置中管理。
- 热点服务允许 HTTP 和 HTTPS 地址；HTTP 会明文传输 Token，公网使用时建议 HTTPS。
- 不展开未显示的长文，不补取尚未加载的主帖或完整会话，不解析图片或视频；纯媒体无文字的回复对象会提示暂不支持。X 改版可能需要更新选择器。
- 不自动填写或发布。事实、语气仍需你审核；界面是 Unicode 字符计数，是否超出发布限制以 X 为准。

### 原创曝光每日记录

在 X 的 Creator Studio 中进入 Original Content Rewards（原创内容奖励）页面，插件会自动采集页面显示的近 90 天已认证用户首页时间线曝光，不含回复。登录账号须与设置中的主页账号一致。

自动采集按北京时间每天 10:00 切换数据日期：10:00 前归昨天，10:00 起归今天。首次保存；新日期的数值未变化时等待更新，发生变化才新增。同一天数值继续变化时更新该日记录，下降和零值也可保存。使用「手动添加 / 修正」可指定日期和整数曝光量，补录历史或修正同日数据；手动值不会被同日自动采集覆盖。页面缩写（例如 23.6K）换算为近似数，同时保留原值。未打开页面时不会产生记录。

「我的数据」显示原创曝光历史，JSON 导出包含 `impressions`；CSV 仍为帖子明细。帖子列表默认按发布时间从新到旧排列。原创曝光沿用本机缓存、自动上传与离线重试机制，清除本机缓存也会清除本机曝光历史。更新后重新加载扩展、刷新 X，并重启本地帖子服务；远程服务需更新 `server.mjs` 和 `analytics-data.mjs`。
