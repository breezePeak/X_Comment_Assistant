# X 评论助手 v1.0.5

无需构建的 Chrome Manifest V3 扩展：点击 X 帖子的回复按钮，侧边栏读取该帖，调用你选择的 AI 厂家和模型，生成三条可编辑、一键复制的评论，再由你粘贴发布。

## 功能

| 功能 | 说明 |
| --- | --- |
| 点击回复即读帖 | 从 X 网页 DOM 读取正文、作者、链接和引用内容，也支持补读已打开的回复弹窗。 |
| 主帖与评论上下文 | 回复评论时结合已加载的主帖背景，区分主帖作者与当前评论者。 |
| 三条候选 | 根据语境生成不同角度的回复，可编辑后复制；支持更充实的表达和恰当的诗词、比喻。 |
| 外语中文参考 | 外语候选附完整中文译文，复制时只复制评论原文。 |
| 多厂家、多模型 | 每家使用独立地址与 Key，通过按钮逐个添加模型，统一在设置页切换。 |
| API 连通测试 | 向选定模型发送 `1+1=？`，显示实际回答和耗时。 |
| 紧凑侧边栏 | 帖子默认两行预览，评论框自动增高，支持展开全文和手动重新读取。 |

## 安装与更新

安装无需 Node.js、npm 或打包工具。先克隆本仓库，或从 GitHub 的 **Code → Download ZIP** 下载并解压：

```sh
git clone https://github.com/breezePeak/X_Comment_Assistant.git
```

1. 使用 Chrome 116 或更新版本，打开 `chrome://extensions` 并开启「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本项目的 **extension 文件夹**，不要选择项目根目录。
3. 如果使用 ZIP 安装包，先解压，再加载包含 `manifest.json` 的文件夹。
4. 固定插件图标，刷新已经打开的 X 页面，打开侧边栏，点击齿轮进入 API 配置。

更新时用新版文件覆盖**原来的插件目录，保持路径不变**，点击扩展的「重新加载」，刷新 X 并重新打开侧边栏与设置页。v1.0.5 会保留旧版的厂家、地址、Key、模型列表、语言和写作偏好；侧边栏底部显示版本号。旧版候选缓存不再复用，下次生成使用新版写作要求。

**日常使用：**打开 X → 点击目标帖子的回复按钮 → 检查侧边栏的回复对象 → 编辑或挑选候选 → 点击「复制评论」→ 回到 X 粘贴并自行发布。

## 多厂家、多模型配置

1. 编辑默认厂家，或点击「新增厂家」。每家填写独立名称、API 地址、Key 和模型列表。
2. 在「该厂家的模型」点击「＋ 添加模型」，逐个填写实际模型 ID，每个独立输入框可编辑或删除；再从「当前模型」选择用于测试和生成的模型。旧版文本域中的模型会自动显示为独立行。
3. 点击「保存全部配置并授权」，允许这些 API 域名。每家的 Key 独立保存，新增或删除厂家需要保存后生效。
4. 厂家与模型统一在设置页切换，保存后回到侧边栏点击「重新生成」。主页面不显示厂家或模型信息，不会自动换厂家或重试。

| 配置 | 说明 |
| --- | --- |
| 厂家名称 | 方便自己区分，例如商汤日日新、DeepSeek、自建网关。 |
| API 地址 | 服务商的 Base URL，自动拼接 `/chat/completions`；也接受完整接口地址。 |
| 该厂家的模型 | 用「添加模型」逐个新增实际模型 ID，例如 `sensenova-6.8-flash-lite`；共用所属厂家的地址和 Key。 |
| API Key | 在对应服务商后台申请；每家独立配置。 |

SenseNova 示例：Base URL 为 `https://token.sensenova.cn/v1`，模型 ID 为 `sensenova-6.8-flash-lite`。初始 DeepSeek 地址和模型是示例，可按需替换。

支持标准的 Chat Completions 请求和 `choices[0].message.content` 响应。仅网页聊天登录、Responses 或 Messages 专有接口不能直接使用；HTTP 仅允许本机 `localhost` 与 `127.0.0.1`。

切换编辑的厂家时，未保存的编辑保留在当前配置页；关闭页面会放弃这些未保存编辑。「清除当前 Key」会立即清除当前厂家的已保存 Key，其他厂家不受影响。新增或删除模型保存后生效；删除当前模型会选中该厂家剩余的第一个模型。每家至少保留一个有效模型才能保存。保存配置页会应用页面上选中的厂家与模型。

## 测试接口

选择厂家与模型，点击「测试当前模型：1+1=？」；可以测试未保存的配置，结果显示实际回答与耗时。测试不会自动保存配置，可能消耗少量 API 额度；测试成功后仍需保存才能用于评论生成。

测试只验证接口能返回文本，不保证模型能正确计算或生成合格的三条评论。未授权、鉴权失败、网络异常和空回答会明确提示，60 秒无响应会终止。修改配置或切换厂家会取消旧测试。

## 生成评论

在 `x.com` 或 `twitter.com` 点击帖子的回复按钮，插件读取网页 DOM 中的原帖正文、作者及引用内容，自动生成「观点补充」「自然共鸣」「真诚提问」三条候选。可编辑、复制，再到 X 按 `Ctrl+V` 粘贴。

默认回复更充实、有层次：内容充分时，中文主帖回复约 80—140 字，评论回复约 50—100 字，外语约 30—45 词；每条原文最多 280 个 Unicode 字符。允许自然使用贴合语境的诗词、典故和比喻，同时要求不编造出处、不堆砌辞藻，不为凑长度捏造内容。实际长度与写作质量仍由模型决定。

非中文候选在原文下方显示「中文参考」，同一次生成同时返回原文与完整译文，不额外发起翻译请求。「复制评论」仅复制原文；中文译文不计入原文字符数。编辑原文后会提示译文对应编辑前内容。模型漏掉外语候选的中文译文时会明确报错，可以展开原始回答检查并重新生成。

回复帖子下面的评论时，同时读取详情页中已加载的主帖，或回复弹窗中显示的上文，分别发送主帖背景和直接回复的评论，生成「自然回应」「轻松互动」「友好延伸」三条候选。主帖滚出页面 DOM 后，在同一详情页内保留已读背景；切换详情页后清除。无法读到主帖时侧边栏会提示，模型只根据当前评论作答，不猜测背景。推荐区帖子不附带当前主帖。

侧边栏默认将主帖和回复对象各压缩为两行预览，点击「展开全文」可查看完整的已读取文字；预览折叠不会截断发送给 AI 的正文。「语言与回复要求」默认折叠，评论框随文字和窗口宽度自动增高，避免框内滚动。窗口较矮或评论较长时，整个侧边栏仍可能需要滚动。

回复弹窗已打开时，打开侧边栏会补读，也可点击「重读帖子」。原帖没有链接时仍能读取文字；可明确匹配同作者和正文的时间线帖子时恢复真实链接，不会猜测 URL。未连接页面时会提示刷新 X。

语言与偏好可在配置页设置，侧边栏支持本次语言和补充要求。切换帖子、厂家或模型会取消旧请求，避免串帖或串模型。候选按标签页暂存于当前浏览器会话，仅复用匹配帖子、厂家、模型和默认写作配置的当前缓存。刷新或关闭标签页会清除对应缓存；直接编辑候选框的文字不会写入缓存，切换前请先复制。

## 模型回答格式

兼容规范 JSON、说明或代码块包裹的 JSON、评论数组、字符串数组以及三条按 `1.`、`2.`、`3.` 编号的评论。双语 JSON 使用 `text` 和 `translation` 分别存放原文与中文译文；编号文本可用单独一行 `中文译文：…`。仍检查三条、非空、不重复、原文和译文长度，不会把任意一段文字硬拆成三条。根据文字脚本识别主要语言，极短混合语句仍需人工核对。

无法识别时可展开「查看模型原始回答」检查最终回答，最多显示前 10000 个字符；服务商标记截断时会明确提示。只读取 `content`，不把 SenseNova 的 `reasoning` 字段当作评论。不自动发起额外付费修复请求。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 点击回复后仍显示等待选择帖子 | 先确认扩展已启用；更新扩展后刷新 X，打开回复框，再点击侧边栏「重读帖子」。 |
| 提示没有主帖背景 | 回到主帖详情页并等待正文加载，再选择要回复的评论；插件不会通过 X 接口补取未加载的内容。 |
| 1+1 测试正常，但生成失败 | 连通成功只表示接口能返回文本。展开模型原始回答，检查是否有三条候选、外语候选是否附中文译文，以及是否被服务商截断；必要时更换模型。 |
| API Key 无效、余额不足或请求受限 | 在服务商后台检查 Key、权限、余额和额度；确认模型 ID 属于当前厂家。 |
| 修改厂家或模型后没有应用 | 在设置页保存全部配置，回到侧边栏点击「重新生成」。只测试接口不会保存配置。 |
| 外语原文编辑后中文没有变化 | 中文参考对应生成时的原文，不会在每次编辑时调用接口；可重新生成，或人工核对修改后的表达。 |
| 无法复制 | 选中候选原文后按 `Ctrl+C`；插件不会替你填入 X 回复框。 |

## 隐私与限制

- 读取网页 DOM，插件不调用 X 的帖子数据接口，不批量抓取时间线，不读取登录 Cookie 或私信。
- 点击回复或手动重读后，将当前回复对象及已读取的主帖背景（文字、作者、链接、引用内容和媒体标记）直接发送至你选择的厂家；API 服务商的处理政策以该服务商为准。
- 所有厂家 Key 只保存于本机 `chrome.storage.local`，仅供扩展自身页面访问，不云同步，不经过本项目服务器。存储不是加密保险箱，请使用可信设备。
- 安装时只申请 X / Twitter 网站访问、侧边栏、存储和写剪贴板；保存时按填写的厂家申请 API 域名访问，测试仅申请当前厂家域名。移除厂家不会撤销旧域名授权，可在 Chrome 扩展权限设置中管理。
- 不展开未显示的长文，不补取尚未加载的主帖或完整会话，不解析图片或视频；纯媒体无文字的回复对象会提示暂不支持。X 改版可能需要更新选择器。
- 不自动填写或发布。事实、语气仍需你审核；界面是 Unicode 字符计数，是否超出发布限制以 X 为准。

## 开发与验证

原生 JavaScript / HTML / CSS，无 npm 依赖，不需要构建。修改后重新加载扩展并刷新 X。

```text
extension/
  manifest.json     扩展入口、权限与资源声明
  background.js     消息校验、侧边栏和会话存储
  content.js        X 网页帖子及主帖背景读取
  core.js           配置验证、提示词、API 请求与回答解析
  options.html/js   厂家、模型、Key 与接口测试设置
  sidepanel.html/js 帖子预览、候选编辑、中文参考和复制
  styles.css        侧边栏与设置页样式
  icons/            扩展图标
tests/
  run.mjs           无外部依赖的核心测试
  browser.cjs       使用模拟页面与接口的 Chrome 回归
```

核心测试在项目根目录运行：

```sh
npm test
```

运行 `npm test`：20 项核心测试覆盖写作要求、双语解析与译文验证、主帖背景验证、回复对象与提示词、上下文缓存标识、旧配置迁移、厂家和 Key 隔离、格式兼容、API 请求与错误、消息边界及 Manifest 资源。

浏览器回归脚本为 `tests/browser.cjs`，需本机已有 Playwright。通过 `NODE_PATH` 指向其 `node_modules`，运行 `node tests/browser.cjs`；可用 `CHROME_PATH` 指定 Chrome 可执行文件，否则使用 Playwright 自带 Chromium。覆盖模型逐行增删和编辑、设置中的模型切换、请求路由、主页面隐藏模型信息、双语显示与仅复制原文、译文安全展示、主帖与评论提取、跨页面背景隔离、弹窗恢复、两行预览与全文展开、不同宽度下编辑评论无内部滚动、厂家与 Key 隔离、1+1 测试及原有回答兼容回归。

也可临时安装测试工具并使用本机 Chrome，以下为 PowerShell 示例：

```powershell
npm install --no-save --package-lock=false playwright
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
node tests/browser.cjs
```

运行浏览器回归需要支持 Playwright 的 Node.js 环境。测试截图写入 `artifacts/`；该目录、`node_modules/` 和本地 ZIP 安装包均不提交到仓库。

已根据真实 X 回复弹窗 DOM 修复无链接读取，曾在独立 Chrome 中实际加载扩展验证读帖链路、旧配置保留、多厂家编辑、模型切换与原生存储。v1.0.5 在真实 Chrome 中使用模拟页面和 API 响应完成回归，并检查了双语侧边栏与模型管理设置的截图。尚未使用真实 API Key 进行付费验证。

## v1.0.5 更新

- 默认回复更充实，允许自然使用贴合语境的诗词、典故和比喻。
- 外语候选提供中文参考，复制原文与译文分离；编辑后标记译文对应的原始版本。
- 模型列表改为独立输入行，通过按钮添加、编辑和删除，保留旧配置。
- 厂家与模型统一在设置页切换，主页面保留帖子预览和评论操作。
